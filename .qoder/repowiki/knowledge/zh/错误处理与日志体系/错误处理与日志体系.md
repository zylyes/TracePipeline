## 1. 采用的系统/方法

本项目采用分层异常 + 结构化 JSON 日志的错误处理方案：
- 业务层：定义专用异常类型（如 TraceValidationError），通过 ValueError 表达配置/数据校验失败，由上层统一捕获并转换为不可变结果对象。
- 流水线层：run_pipeline 使用 _handle_pipeline_error 将任意异常包装为 RunResult.failure(...)，附带 error_type、可选 traceback，供前端轮询消费。
- 服务层：PipelineService._run_background 对每个子任务单独 try/except，关键异常（MemoryError、SystemExit、KeyboardInterrupt）直接上抛，普通异常转为失败结果继续处理其他目标。
- 日志层：自定义 JsonFormatter + DailyRotatingJsonHandler，所有日志输出为单行 JSON Lines，按天分目录、自动归档 zip、支持大小分片；主进程与 worker 进程分别写入不同文件，避免竞态。

## 2. 核心文件与包

- trace_pipeline/io/excel_reader.py：定义 TraceValidationError(ValueError)，Excel 读取时区分格式错误与 sheet 不存在，前者直接上抛、后者回退首表
- trace_pipeline/validation.py：纯函数式配置校验器（coerce_*），全部以 ValueError 返回，消息包含字段名
- trace_pipeline/pipeline.py：_handle_pipeline_error 统一封装异常为 RunResult.failure；run_pipeline 在子进程中初始化独立日志后端
- backend/services/pipeline_service.py：后台线程 + ProcessPoolExecutor 调度，逐任务捕获异常，记录 logger.error(..., extra={stage,error,error_type})，向队列推送 file_complete 事件
- trace_pipeline/logging/core.py：JsonFormatter、DailyRotatingJsonHandler、setup_logging / setup_worker_logging，实现 JSON Lines 日志、按天归档、大小分片、多进程隔离
- trace_pipeline/logging/context.py：LogContext 上下文管理器注入 request_id，跨 logger 关联同一次请求

## 3. 架构与约定

- 异常分类：TraceValidationError（继承 ValueError）用于数据/文件格式问题，调用方应直接上抛不做重试或回退；通用 ValueError 用于配置项非法，由 validation.coerce_* 抛出，消息形如 "xxx 必须为正整数"；运行时异常（IO、权限等）由 pipeline.run_pipeline → PipelineService 捕获，转为 RunResult.failure(error_type=type(exc).__name__)。
- 结果对象：RunResult 是不可变的成功/失败载体，status 枚举值驱动前端展示，error/error_type/error_traceback 提供诊断信息。
- 日志规范：所有业务日志通过 logger.info/warning/error(..., extra={stage: ..., ...}) 附加结构化字段；关键路径（加载、变换、绘图、导出）均记录耗时 duration_ms；子进程通过 setup_worker_logging 写入 worker_{pid}.jsonl，主进程负责归档旧日目录为 YYYY-MM-DD.zip。
- 无 panic/recover：Python 侧未使用 try/finally 之外的恢复机制，也不存在 panic 语义；优雅关闭通过 shutdown_event + join(timeout) 实现。

## 4. 开发者应遵循的规则

1. 不要吞掉关键异常：MemoryError、SystemExit、KeyboardInterrupt 必须重新 raise，不得被 except Exception 捕获。
2. 校验失败一律抛 ValueError：在 validation.py 的 coerce_* 中集中写规则，消息需指明字段名，便于前端提示。
3. Excel 读取失败用 TraceValidationError：仅用于数据格式错误；sheet 不存在走回退逻辑，不抛异常。
4. 所有外部 I/O 调用包裹 try/except：记录 logger.error(..., extra={stage, error, error_type})，并将异常转为 RunResult.failure 返回。
5. 使用 LogContext(request_id=...) 包裹长任务，确保同一请求的日志可聚合。
6. 不要在 worker 中操作主日志目录的 zip 归档：DailyRotatingJsonHandler.__init__ 已内置 MainProcess 判断，子进程只写 worker_{pid}.jsonl。
7. 禁止使用 logging.exception() 以外的方式打印堆栈：需要完整 traceback 时通过 include_traceback=True 传入 _handle_pipeline_error，由 JsonFormatter.formatException 序列化到 exc_info 字段。
