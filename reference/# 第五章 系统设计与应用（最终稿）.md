# 第五章 系统设计与应用（最终稿）


## 5. 系统设计与应用

第四章详细阐述了从测线法原始参数（r₁–r₇、倾向）到二维迹线坐标再到统计参数的算法原理与工程实现。本章在此基础上，从软件工程角度系统介绍整套数字化重构工具的模块架构设计、三层用户接口设计以及8个花岗岩露头（O76–O83）的批量处理结果展示，完整呈现该工具从底层算法到顶层应用的工程化实现路径。

### 5.1 模块架构设计

本系统以Python 3.10+为开发语言，以NumPy向量化计算、Matplotlib科学可视化及openpyxl/xlrd结构化数据I/O为三大技术支柱，严格遵循"不可变数据模型—纯函数计算—向量化优先"三项核心设计原则[1]，构建了四层模块架构：数据模型层→流水线编排层→核心计算层→I/O与绘图层。各层之间职责明确、依赖单向，高内聚低耦合，整体架构如图5-1所示。

**（1）数据模型层**

系统顶层定义了7个核心不可变数据类（均以`@dataclass(frozen=True)`装饰器声明为冻结数据类），全部位于`trace_pipeline/models.py`与`trace_pipeline/geology/_stat_types.py`中[2]：

- `TraceData`：封装单露头的全部原始输入参数（r₁–r₇数组、倾向数组、测线方位、迹线条数等），在Excel加载阶段一次性构造，后续各层仅读取不修改；
- `RunConfig`：承载运行期全部配置参数（输入/输出路径、玫瑰图分箱宽度、圆窗策略选择、DPI设置、并行线程数、凸包缓冲系数等12项），支持JSON配置文件加载与CLI参数覆盖；
- `RunResult`：汇总单个露头流水线执行完毕后的全部输出信息（端点坐标数组、`TraceStatistics`统计对象、输出文件路径列表、处理耗时等），作为流水线编排层的标准返回类型；
- `TraceStatistics`：容纳完整的迹线统计信息——P₁₀/P₂₀/P₂₁及其三级来源标注(M)/(E)/(W_eq)、I/II/III型迹线分类计数、有效窗口数及策略名称、Terzaghi方向修正线密度、IPW逆概率加权无偏迹长估计等[3]；
- `TraceStatisticsConfig`：独立封装统计算法的可调参数（四级回退容差、圆窗最小相交数、auto策略6因子权重字典、IPW截断阈值等），便于统计算法模块的参数集中管理；
- `CircleWindowDiagnostic`：记录圆形取样窗策略的诊断元数据（窗口数量与分组、各组n₀/n₁/n₂分类计数、各指标变异系数CV、策略评分明细等），供策略调试与结果审计使用；
- `EndpointResult`：保存端点计算的中间结果（三种情形的布尔掩码、折叠后方向角弧度值、L₀复坐标等），供算法验证与MATLAB对比时引用。

所有7个dataclass均在构造时完成NumPy数组的只读设置（`arr.flags.writeable = False`），确保数据在流水线各阶段传递过程中不被意外修改，从根本上消除了状态副作用类bug的产生可能[2]。

**（2）流水线编排层**

`trace_pipeline/pipeline.py`中的`run_pipeline(trace_data, config) -> RunResult`函数是单露头全流程的编排核心[3]。该函数接收一个`TraceData`实例和一个`RunConfig`实例，依次调度以下八个处理阶段并返回`RunResult`：

① Excel读取与表头校验（`io/excel_reader.py`）：按§3.5.2表3-5定义的列映射关系解析r₁–r₇，自动检测表头行号、跳过空行、将非法值替换为NaN，并提取测线走向角（第8列）与迹线条数（第9列）。

② 倾向→走向批量转换（`geology/angles.py`）：调用`dip_to_strike()`函数，利用`np.select`向量化三段式分段映射，将n条迹线的倾向角（0°–360°）一次性转换为走向角。

③ 复数向量化端点坐标计算（`geology/endpoints.py`）：调用`compute_endpoints()`函数，在复平面中构建测线局部坐标系，执行基准角两段式计算→三种情形布尔掩码自动分流→复数指数函数批量生成方向向量→数组广播缩放与合成，输出形状为(n, 2, 2)的端点坐标数组。

④ 坐标标准化三步变换（`geology/transforms.py`）：调用`normalize_coordinates()`函数，依次执行"平移至正象限→走向旋转→再次平移"流水线，将局部坐标转换为全局标准化坐标，并写入输出Excel的C区（旋转坐标区）。

⑤ 迹线几何参数统计（`geology/statistics.py`编排层联合6个私有子模块）：依次执行I/II/III型自动分类→四级回退面积与迹线总长度估计→圆形取样窗法自适应策略选择与Mauldon迹长估计→Terzaghi方向修正与IPW无偏迹长估计，返回`TraceStatistics`对象。

⑥ 四区Excel布局导出（`io/excel_writer.py`）：将处理结果按A区（基本信息）、B区（原始端点坐标）、C区（旋转后端点坐标）、D区（走向与迹长）的四区布局写入输出Excel文件[3]。

⑦ 迹线图绘制（`plotting/trace_plot.py`）：生成原始迹线图（300 DPI）和旋转后标准化迹线图（600 DPI），后者内置比例尺、指北针、LaTeX统计信息框（10行指标）及凸包/圆窗覆盖层。

⑧ 玫瑰花图生成（`plotting/rose_plot.py`）：生成节理走向玫瑰花图（默认10°分箱、400 DPI），支持自定义分箱宽度与分辨率。

流水线编排层同时包含`config.py`（JSON配置加载、校验、CLI参数覆盖与合并）和`reporting.py`（多露头结果格式化与批量汇总报告），共同构筑从配置输入到结果汇总的完整调度链路[2]。

**（3）核心计算层（geology/子包）**

geology/子包是本系统的数学计算内核，包含5个公开模块和6个私有子模块，所有函数均为纯函数——接收NumPy数组，返回NumPy数组，无文件I/O、无全局状态修改、无副作用[2]。公开模块的功能已在第四章§4.1表4-1中详列，此处从架构组织角度补充说明私有子模块的职责分工[3]：

- `_stat_types.py`：定义`TraceStatistics`和`TraceStatisticsConfig`两个核心统计dataclass，以及`AreaSource`、`LengthSource`等枚举类型，为统计模块提供类型基础；
- `_stat_format.py`：负责LaTeX统计信息框的字符串格式化，包括数值精度控制（4位有效数字）、来源标注符号(M)/(E)/(W_eq)的生成与对齐；
- `_circle_window.py`：实现Mauldon（1998）圆形取样窗法的核心计算——给定窗口半径与端点坐标，计算n₀/n₁/n₂分类计数，并依据公式(4-24)(4-25)输出P₂₀和平均迹长的闭式估计；
- `_convex_hull.py`：实现Andrew单调链凸包算法（O(n log n)），用于从端点坐标计算露头有效面积；同时提供缓冲凸包外扩函数（默认外扩0.25倍平均迹长）；
- `_window_strategies.py`：实现tangent（相切圆）、hybrid（混合）、concentric（同心圆）三种圆窗布置策略的窗口坐标生成逻辑，以及auto自适应策略的策略编排与降级兜底逻辑；
- `_window_scoring.py`：实现auto策略的6因子加权评分函数——有效组数（权重×1.45）、有效组比例（×1.00）、空间覆盖（×1.35，含双侧平衡度0–0.85分与沿测线三分区覆盖率）、指标稳定性（×1.10）、半径尺度（×1.00）、样本充足率（×1.10），并按12%容差阈值的密度偏好策略执行回退判定[3]。

（4）I/O与绘图层

I/O层（`trace_pipeline/io/`）负责结构化数据的读写与输入目录自动扫描。`excel_reader.py`支持.xlsx（openpyxl引擎）与.xls（xlrd引擎）双格式回退读取，自动检测表头行号并根据列索引映射（列0= r₁, 列1= r₂, 列2= dip, …, 列7= ang₀）解析参数[3]；`excel_writer.py`使用openpyxl的`WriteOnlyWorksheet`模式流式写入大量坐标数据，避免内存溢出；`discovery.py`实现`input/`目录下`*_process.xls*`文件的自动扫描、去重与排序。

绘图层（`trace_pipeline/plotting/`）采用惰性导入（lazy import）策略——仅在首次调用绘图函数时才导入Matplotlib及相关后端，将CLI模式下非可视化运行的启动时间缩短约40%[2]。`trace_plot.py`的装饰元素（比例尺、指北针、图例、统计信息框）采用自动避让布局算法：优先置于图框右下角，若与迹线或凸包边界重叠则依次尝试左上角、左下角和右上角[3]。`style.py`实现了CJK（中日韩）字体的多级回退机制——依次尝试SimHei → Microsoft YaHei → Noto Sans CJK SC → WenQuanYi Micro Hei → sans-serif，确保LaTeX统计信息框中的中文指标名称在Windows/Linux/macOS跨平台环境中的正常渲染[3]。

### 5.2 三层用户接口

为满足终端用户、开发者和非编程地质工作者三类不同场景下的使用需求，本系统设计了三层用户接口：命令行接口（CLI）、Python编程接口（API）以及Web图形界面（Streamlit，预留）。

**（1）命令行接口（CLI）**

命令行接口通过项目根目录下的`run_trace_pipeline.py`入口脚本调用，基于Python标准库`argparse`模块实现，共支持12个独立参数[3]：

| 参数 | 简写 | 类型 | 默认值 | 说明 |
|------|------|------|--------|------|
| `--input` | `-i` | str | `config.json`中的`input_dir` | 输入目录路径 |
| `--output` | `-o` | str | `config.json`中的`output_dir` | 输出目录路径 |
| `--config` | `-c` | str | `config.json` | 自定义JSON配置文件路径 |
| `--single` | `-s` | flag | False | 单文件模式：仅处理`table_stem`指定的露头 |
| `--list` | `-l` | flag | False | 列出`input/`目录下发现的全部迹线表文件后退出 |
| `--interactive` | `-I` | flag | False | 交互模式：由用户从文件列表中选择处理目标 |
| `--dry-run` | `-n` | flag | False | 试运行：打印待处理清单但不实际执行 |
| `--parallel` | `-p` | int | 0（串行） | 并行处理线程数 |
| `--rose-bin` | — | float | 10.0 | 玫瑰花图分箱宽度（°） |
| `--rose-dpi` | — | int | 400 | 玫瑰花图分辨率（DPI） |
| `--no-rose` | — | flag | False | 跳过玫瑰花图生成以加速 |
| `--window-strategy` | — | str | `auto` | 圆窗策略：auto/tangent/hybrid/concentric |

CLI支持四种运行模式以满足不同场景需求[3]：①**批量模式**（默认，`python run_trace_pipeline.py`）：自动扫描`input/`目录下全部`*_process.xls*`文件，配合tqdm进度条逐一完成8个露头的完整处理流水线；②**单文件模式**（`-s`）：仅处理指定露头，适用于参数调试与单露头详细分析场景；③**交互模式**（`-I`）：终端列出可处理文件清单，用户通过键盘输入编号选择目标，适用于不熟悉命令行的用户；④**并行模式**（`-p N`）：以N线程并发处理多个露头，在多核CPU环境下总耗时可由串行约45秒降至约18秒（4线程实测）。此外，试运行（`-n`）和文件列表（`-l`）两种辅助模式便于使用者在正式处理前确认输入数据的完整性与可处理性[3]。

日志系统采用Python标准库`logging`模块实现双通道输出[3]：控制台StreamHandler实时显示INFO级别信息（当前处理露头编号、迹线条数、平均迹长、P₁₀/P₂₀/P₂₁关键统计值），文件RotatingFileHandler异步写入DEBUG级别详细日志（`logs/pipeline_YYYYMMDD_HHMMSS.log`，自动保留最近7份日志文件，单份上限10 MB），便于事后问题排查与处理过程审计。

**（2）Python编程接口（API）**

本系统顶层包`trace_pipeline`通过`__init__.py`导出了20个公开API入口，覆盖从数据模型构造、配置管理、流水线执行到统计计算的完整功能链[2]。核心API的函数签名与功能如下：

- `run_pipeline(trace_data: TraceData, config: RunConfig) -> RunResult`：执行单露头的完整八阶段处理流水线，返回汇总结果对象；
- `load_trace_data(excel_path: str | Path) -> TraceData`：从Excel文件路径加载并校验迹线原始数据，对非法值自动标记并输出警告日志；
- `compute_endpoints(trace_data: TraceData) -> EndpointResult`：执行复数向量化端点坐标计算，返回包含三种情形掩码和全部端点坐标的中间结果对象；
- `normalize_coordinates(endpoints: np.ndarray, azimuth_deg: float, margin: float = 1.0) -> np.ndarray`：执行平移→旋转→再平移三步坐标标准化变换；
- `compute_trace_statistics(endpoints: np.ndarray, trace_data: TraceData, config: TraceStatisticsConfig) -> TraceStatistics`：在端点坐标基础上执行完整的迹线几何参数统计计算；
- `dip_to_strike(dip_angles: np.ndarray) -> np.ndarray`：倾向→走向的三段式向量化批量转换；
- `fold_to_halfplane(base_angle_deg: float, target_angles_deg: np.ndarray, invert: bool = False) -> np.ndarray`：半平面角折叠的四步算法；
- `fold_strike_angle(azimuth_deg: float) -> float`：走向角规范化折叠至[−90°, 90°]区间并转为弧度。

所有底层模块的公开函数同样可直接导入调用，例如：

```python
from trace_pipeline.geology.angles import fold_strike_angle
from trace_pipeline.geology.statistics import TraceStatisticsConfig
from trace_pipeline.io.excel_reader import discover_input_files
```

这种层次化的API设计使本系统既可封装为独立的命令行工具一键运行，也可作为Python库嵌入到更复杂的岩体结构分析工作流中——例如在节点拓扑识别模块中复用端点坐标数组，或在三维DFN建模模块中复用`TraceStatistics`对象作为输入参数——为后续功能扩展提供了灵活的集成接口[2]。

**（3）Web图形界面（Streamlit，预留）**

除命令行和API接口外，本系统预留了基于Streamlit框架的Web图形界面架构设计[2]。该Web界面旨在为非编程背景的地质工作者提供直观的交互式操作环境，拟包含文件上传与参数配置面板、迹线图实时预览（支持缩放、平移与图层切换）、统计结果仪表板（密度参数表格、迹长分布直方图、I/II/III型分类饼图及走向玫瑰花图）及多露头批量结果对比四个功能模块。该模块作为可选扩展，原型实现约需2天工作量，论文中仅给出架构说明。

从表5-1可归纳以下规律[3]：①迹线类型分布以Ⅰ型（相交型）占绝对主导，仅O76（7条Ⅱ型）、O77（5条Ⅱ型）、O78（6条Ⅱ型）含少量Ⅱ型迹线，Ⅲ型在所有露头中均未出现，与戈壁花岗岩露头节理连续性好的野外观察一致。②线密度P₁₀分布在0.57–2.20 m⁻¹之间，O81（2.20 m⁻¹）和O83（2.18 m⁻¹）最高，其测线方位（75°和265°）近似与区域主要节理组走向垂直；O79（0.57 m⁻¹）最低，测线方位（212°）与主要节理组走向夹角偏小。③平均迹长跨度4.99–14.27 m，O81最大（14.27 m），O82最小（4.99 m），反映不同露头部位节理发育规模的显著空间差异。④上述统计规律与霍亮等（2019, 2023）在北山沙枣园花岗岩体中的多尺度研究结论——结构面间距总体服从负指数分布、迹长适宜采用对数正态分布描述——基本吻合[1]。⑤auto策略对8个露头中的7个选择了concentric策略（6个同心圆窗），仅O81选择了hybrid策略（18个混合窗口），自适应判定结果与各露头迹线密度及空间分布特征相匹配，验证了6因子加权评分机制的有效性。

**（2）典型露头O80可视化结果**

O80露头（29条迹线，测线走向334° NNW向）是8个露头中迹线数量最多的典型代表[3]。其旋转后标准化迹线图如图5-3所示（600 DPI，含LaTeX统计信息框）。图中测线方向已旋转至与x轴正向对齐，各迹线以蓝色实线（Ⅰ型）和橙色虚线（Ⅱ型）区分，同时叠加了concentric策略的6个同心圆形取样窗（蓝色虚线圆）、Andrew单调链凸包边界（灰色实线多边形）及缓冲凸包外扩边界（灰色虚线）。图框右下角标注比例尺与指北针，左侧LaTeX统计信息框内嵌了原始平均迹长（含来源标注）、P₁₀（含Terzaghi修正值）、P₂₀/P₂₁（含来源标注M/E/W_eq）、加权与无偏平均迹长、I/II/III型分类计数及有效窗口数等10行统计指标[3]。

O80露头的迹线图直观揭示了该部位节理发育的两个显著几何特征：一是迹线以近NW–SE向延伸为主，与测线方位334°近于垂直相交，截取效率较高（P₁₀ = 1.1959 m⁻¹）；二是迹线沿测线方向的空间分布较为均匀，concentric策略的6个同心圆窗在测线近端、中端和远端三个分区内均有良好的空间覆盖率，P₂₀的凸包面积估计值（0.0725 m⁻²）与圆窗估计值接近，表明凸包面积在该露头中具有较好的面积代表性[3]。

**（3）输出文件的结构化组织**

每个露头经流水线处理后产生4个标准输出文件，8个露头共生成32个文件，统一存放于`output/`目录下[3]：

- `{露头编号}_traces.xlsx`：四区布局Excel文件（A区：基本信息含测线走向、测线长度、平均迹长、露头面积及完整10行统计指标；B区：原始端点坐标（起点x/y、终点x/y）；C区：旋转后端点坐标（标准化变换后的坐标）；D区：走向与长度（节理走向角、端点欧氏距离、测段长度r₅+r₇、迹线类型分类）），是数字化重构的核心数据输出；
- `{露头编号}_raw(n={迹线数}).png`：原始局部坐标系迹线图（300 DPI），含比例尺与指北针；
- `{露头编号}_rotated(strike={走向角}).png`：旋转后标准化迹线图（600 DPI），含LaTeX统计信息框、凸包/缓冲凸包/圆窗覆盖层及自动避让布局的装饰元素，是论文中直接引用的主要可视化成果；
- `{露头编号}_rose(bin={分箱宽度}).png`：节理走向玫瑰花图（默认10°分箱、400 DPI），直观展示各露头节理走向的优势分布方向。

### 5.4 本章小结

本章从软件工程角度完整阐述了基于Python的花岗岩露头节理网络数字化重构系统的模块架构、用户接口与批量处理成果。通过四层模块架构（数据模型层→流水线编排层→核心计算层→I/O与绘图层）的清晰分层设计、三层用户接口（CLI命令行→Python API编程接口→Streamlit Web界面预留）的灵活适配以及8露头172条节理迹线的完整批量验证，本系统实现了从"一维测线记录"到"二维迹线图+标准化Excel输出+LaTeX统计参数表"的全程自动化处理。系统构成了第四章所述算法原理的工程化载体，验证了基于Python进行花岗岩露头节理网络数字化重构的技术可行性与工程实用性，为后续节点拓扑识别、三维离散裂隙网络（DFN）建模等扩展研究提供了可复用的数据处理基础设施。
